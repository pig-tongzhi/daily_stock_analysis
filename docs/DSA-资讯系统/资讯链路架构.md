# 资讯链路架构

这份文档回答两个问题：**资讯从哪来**、**资讯被谁消费**。写它的起因是这两件事此前都不清楚，导致「资讯一直是手动拉的」却不知道能不能自动化、也不知道改了会不会影响别处。

## 全链路一张图

```
                    ┌──────────────────────────────────────┐
                    │  外部站点（财联社/格隆汇/东财/雪球…）  │
                    └──────────────────┬───────────────────┘
                                       │ 抓取
                    ┌──────────────────▼───────────────────┐
                    │  RSSHub :1200      NewsNow :5173     │   转换层
                    │  （RSS/Atom）      （JSON；仅绑 IPv6） │   只做格式转换
                    └──────────────────┬───────────────────┘
                                       │ HTTP
                    ┌──────────────────▼───────────────────┐
                    │  DSA IntelligenceService             │   抓取+入库
                    │  fetch_enabled_sources()             │
                    └──────────────────┬───────────────────┘
                                       │ upsert（6 字段去重）
                    ┌──────────────────▼───────────────────┐
                    │  SQLite: intelligence_items          │   ← 唯一的池
                    │  scope_type = symbol | market        │
                    └──────────────────┬───────────────────┘
                                       │ 读取
        ┌──────────────┬───────────────┼───────────────┬──────────────┐
        ▼              ▼               ▼               ▼              ▼
   个股分析        大盘复盘        股票档案         选股 L2       资讯页
   analyze_stock  market_review  profile        screening      /items
                                                              （只读展示）
```

**关键概念：`scope_type` 决定资讯归属**

| scope_type | scope_value | 含义 | 谁能看到 |
|---|---|---|---|
| `symbol` | 股票代码 | 该股票的资讯 | 只有这只股票的分析 |
| `market` | 市场（cn）| 大盘级资讯 | **所有**股票分析 + 大盘复盘 |

## 一、入口侧：资讯怎么进来

### 会触发拉取的 4 个地方

| # | 位置 | 触发方式 | 说明 |
|---|---|---|---|
| 1 | `POST /intelligence/sources/{id}/fetch` | **手动** | 拉单个源 |
| 2 | `POST /intelligence/sources/fetch-enabled` | **手动** | 拉全部启用源（资讯页「立即拉取」按钮）|
| 3 | `pipeline.py:3030` | 自动 | **个股分析**时顺带拉一次 |
| 4 | `market_analyzer.py:2080` | 自动 | **大盘复盘**时顺带拉一次 |

### ⚠️ 当前的核心问题：没有独立定时抓取

```
NEWS_INTEL_AUTO_FETCH_ENABLED = true     ← 但只在「跑分析」时才生效
SCHEDULE_ENABLED              = false    ← 定时任务关闭
```

**后果**：
- **不跑分析 → 资讯不更新。** 打开资讯页看到的可能是几天前的内容。
- 拉取频率**被动依附于分析频率**，而不是资讯本身的更新节奏。
- 想要资讯新鲜，就得手动点「立即拉取」，或者先跑一次分析。

### 两处节流

| 机制 | 值 | 位置 |
|---|---|---|
| 进程内冷却 | **20 分钟**（可配 `NEWS_INTEL_AUTO_FETCH_MIN_INTERVAL_SECONDS`）| `intelligence_service.py` |
| 上游缓存 | RSSHub 5 分钟 / NewsNow 10~30 分钟 | 转换层自身 |

**冷却是进程内的** —— 重启 DSA 即重置。抓得比上游缓存还快只是拿同一份数据。

### 数据保留

`intelligence_items` 有 **30 天**自动清理（`NEWS_INTEL_RETENTION_DAYS`）。
注意名字陷阱：它清的是 `intelligence_items`，**不是** `news_intel`（那是搜索 API 的另一张表）。

## 二、消费侧：资讯被谁读

**5 个真实消费点 + 1 个只读展示。** 改任何一处前先对照这张表。

### ① 个股分析 —— 最完整的一条

```
POST /analysis/analyze
  → pipeline.analyze_stock (pipeline.py:683 读池)
      → _load_persisted_intelligence_context (pipeline.py:3039)
           两级查找：先 symbol（这只股票）→ 再 market（大盘兜底）
           最多 limit 条，URL 去重
```

**同时被这些入口复用**：`task_queue.py:818`、`analyzer_service.py:94`、`pipeline.py:3368`。

### ② 大盘复盘

```
POST /analysis/market-review
  → market_analyzer._merge_persisted_market_intelligence (market_analyzer.py:2081)
       只取 market scope
```

### ③ 股票档案

```
GET /api/v1/stocks/{stock_code}/profile
  → stock_profile_service._intelligence_block (stock_profile_service.py:191)
       按「别名」逐个 market 查 symbol scope，每别名最多 10 条
       返回结构里的 intelligence 块（status: fresh/stale）
```

### ④ 选股 L2 —— ⚠️ 默认关闭

```
POST /screening/screen
  → screening/intelligence_context.py
       Layer A: market scope → 所有候选共享的今日市场背景
       Layer B: code 精确匹配 或 名称匹配 → 单个候选
```

开关：`SCREENING_INTELLIGENCE_CONTEXT_ENABLED`（**默认 false**，当前未开）。

### ⑤ 资讯页（只读展示，不喂 LLM）

```
GET /api/v1/intelligence/items
```
这是唯一"给人看"的出口。**它不参与任何分析。**

### ❌ 明确不读资讯池的：**问股（Agent 对话）**

已核实：`AgentExecutor.run` 完全不经过 `pipeline`。问股只走**搜索 API**（Bocha），与本地池无关。

> 注意 `pipeline.py:1550` 的 `_analyze_with_agent` 名字像问股，**实际是被 `analyze_stock:664` 调用的同一个功能**（Agent 后端的个股分析）。

## 三、重新编排时该动什么

按影响面排序，前三条是当前最值得做的。

### P0：把拉取从"分析时顺带"解耦出来

**问题**：资讯新鲜度被动依附于分析频率。

**先排除一个看似显然的方案**：`SCHEDULE_ENABLED=true` **不能**解决这个问题。已核实 `runtime_scheduler.py` 是 subprocess 跑**完整分析**（`_run_analysis_once` → `analyze_stock`），里面**没有任何独立的抓取逻辑**。开调度只会变成：

```
每日跑一次分析 → 分析里顺带抓一次 → 抓取频率 = 每日一次
```

抓取节奏仍然由分析决定，而且 20 分钟的进程内冷却在"一天跑一次"下完全失效。

**真正可选的方案**：

- **A. 独立抓取循环（推荐）**：一个轻量线程/进程，每 20~30 分钟调一次 `fetch_enabled_sources()`，与调度器和分析完全解耦。抓取节奏由资讯源本身决定（最快的源 1 分钟一条），不该由分析频率决定。
- **B. 外部 cron**：系统 cron 调 `POST /intelligence/sources/fetch-enabled`。零代码改动，但依赖外部配置、不随服务生命周期走。
- **C. 事件驱动**：只在资讯页被打开 / 分析开始前 N 分钟内没抓过时才抓。折中，但仍有"不打开就不更新"的问题。

**推荐 A。**

### P1：让"谁在读池"变成可见的

现在要弄清一个改动的影响面，只能靠 grep。**建议加一行统一的结构化日志**，在每次注入时打出：

```
intelligence injected: consumer=analyze_stock code=600559 symbol=3 market=6 chars=1820
```

这样任何一次分析跑完，都能从日志直接看出"这次用了多少资讯、来自哪一层"。

### P2：补上缺失的计算面

- **`symbol` 源覆盖的是自选股那几只，不是全市场。** 选股从 5500 只里挑，命中率接近 0（实测 4 个策略 33 个候选，池中 0 命中）。**选股的 Layer B 名称匹配是绕过这个限制的临时办法，不是根治。**
- 真要覆盖全市场，需要**按需建源**（分析/选股到某只股票时，若没有它的 symbol 源则动态创建），这比预建 5500 个源现实。

### P3：把"资讯"和"搜索"两条路的关系写清楚

系统里有**两条独立**的资讯来源，很容易混淆：

| | 本地池 | 搜索 API |
|---|---|---|
| 表 | `intelligence_items` | `news_intel` |
| 来源 | RSSHub / NewsNow | Bocha 等搜索服务 |
| 谁用 | 个股分析、大盘复盘、档案、选股 | **问股** |
| 开关 | `NEWS_INTEL_AUTO_FETCH_ENABLED` | `BOCHA_API_KEYS`（当前未配）|

**它们互不读写。** 问股看不到你辛苦搭的 RSS 源；个股分析也不用搜索 API。

## 四、排查用的速查命令

```bash
# 池子现状
.venv/bin/python -c "
import sqlite3; c=sqlite3.connect('data/stock_analysis.db')
print('总数', c.execute('SELECT COUNT(*) FROM intelligence_items').fetchone()[0])
for r in c.execute('SELECT scope_type, COUNT(*) FROM intelligence_items GROUP BY 1'): print(' ', r)
print('启用源', c.execute('SELECT COUNT(*) FROM intelligence_sources WHERE enabled=1').fetchone()[0])
"

# 手动拉一次（全部启用源）
curl -X POST http://127.0.0.1:8010/api/v1/intelligence/sources/fetch-enabled

# 某个源最近抓取时间与状态
curl -s http://127.0.0.1:8010/api/v1/intelligence/sources | python3 -m json.tool | head -40

# 看某只股票的档案里有没有资讯
curl -s "http://127.0.0.1:8010/api/v1/stocks/600559/profile" | python3 -c "
import sys,json; d=json.load(sys.stdin); i=d.get('intelligence') or {}
print(i.get('status'), len(i.get('items') or []), '条')"
```
