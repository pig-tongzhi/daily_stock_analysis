# 四个功能：怎么实现的，要改什么

按功能维度看的实现地图。架构文档讲分层，这份讲**每个功能从入口到结果的真实路径**，以及它缺什么。

---

## 功能 1 · 选股

### 怎么实现的

```
POST /api/v1/screening/screen
  └→ screen()  src/services/screening/pipeline.py:48
      ① 读策略 YAML（10 个策略）
      ② 取全市场快照        网络  sina/efinance/akshare_em/em_datacenter
                             兜底 data/screening/snapshot.last_good.json
      ③ L1 硬过滤           2,316 → 231 只（dual_low 实测）
      ④ 因子打分            screen_score，9 个因子【硬编码字典】
      ⑤ 取 top-K            min(max_output×2, 12, len) → 生产实际 6
      ⑥ DSA provider 上下文  网络  实时报价/基本面
      ⑦ L2 LLM 排序         网络  final = screen_score×0.6 + llm_score×0.4
      ⑧ 风险 overlay        本地  每个 risk_flag -1.2，上限 -4
      ⑨ 组合分散 overlay     本地  同行业 >1 只则惩罚
      ⑩ L3 scorecard        本地
```

### 缺什么

| # | 问题 | 证据 |
|---|---|---|
| 1 | **资讯两条路都是关的** | `intelligence_context_enabled=False`；AkShare 路径被 `screening_service.py:1934` **强制写 false**，API 永远开不起来 |
| 2 | **资讯只进 prompt，不进数值** | 全部 `classify_*`/`source_weight_score` 只被渲染成文本，没有任何数值读取 |
| 3 | **资讯池与候选交集 = 0** | 池覆盖 6 只，7 个可跑策略的 top-K 全部 0 命中 |
| 4 | **prompt 已到上限** | `top_k=30` 时 23,925/24,000，资讯会挤掉 `candidate_details` |
| 5 | 因子集是冻结的 | `scorer.py:10-20` 硬编码 9 个；YAML 里写 `factor_weights: {news: 0.1}` 会被**静默丢弃** |

### 要改什么

| 阶段 | 改动 |
|---|---|
| 4 | **覆盖策略**：按需建源 + 事件型资讯（实体链接），解决交集为 0 |
| 4 | **进数值层**：`scorer._FACTOR_COLUMNS` + `_compute_factor_scores` 加 news 因子；数据源用**已经算出但被丢弃的** `source_weight_score`/`negative_event_flags` |
| 4 | **join 必须在 `compute_screen_scores` 之前**（`pipeline.py:326`），否则 `context.py:422-424` 会把不在候选池的行丢掉（实测注入 0 字符） |
| 4 | **缓存指纹**：`candidate_context.py:607-609` 的 key 加资讯指纹，否则 24h TTL 内复用陈旧资讯 |
| 4 | **解开强制关闭**：`screening_service.py:1934` 改为尊重配置 |
| 4 | **预算管理**：资讯与候选详情共同分配，**优先保候选详情** |

## 功能 2 · 问股

### 怎么实现的

```
POST /api/v1/agent/chat  （另有 /chat/send, /chat/stream）
  └→ AgentExecutor.run()   src/agent/executor.py:678
      ① 构造 system prompt（技能 + 策略）
      ② 注入记忆           src/agent/agents/base_agent.py:280
      ③ 工具循环（19 个工具）
      ④ LLM 生成回答
```

**19 个工具**：

| 类别 | 工具 |
|---|---|
| data | `get_realtime_quote` · `get_daily_history` · `get_chip_distribution` · `get_analysis_context` |
| market | `get_market_indices` · `get_sector_rankings` |
| analysis | `analyze_trend` · `calculate_ma` · `get_volume_analysis` |
| search | `search_stock_news` · `search_comprehensive_intel` |
| backtest | `get_skill_backtest_summary` · `get_strategy_backtest_summary` · `get_stock_backtest_summary` |

### 🔴 缺什么 —— **两个记忆来源都是空的**

```python
# base_agent.py:280-282
entries = self.memory.get_stock_history(code, limit=3)      # → outcome_5d / was_correct
review  = self.memory.get_decision_signal_review(code)      # → hit_rate / confidence_adjustment
```

**实测**：

```
get_stock_history          读 analysis_history + raw_result 里的 outcome_5d
                           → 扫了 18 条个股分析，raw_result 里【没有任何】outcome 字段
                           → backtest_results 表 0 行

get_decision_signal_review 读 decision_signal_outcomes
                           → 19 行全部 unable → hit_rate = None
                           → confidence_adjustment 永远停在 "observe"
```

> **问股有完整的"记忆"机制，但没有任何可记忆的内容。**
> 它无法说"我上次对这只票的判断错了" —— 因为系统从来没验证过。

| # | 问题 | 证据 |
|---|---|---|
| 1 | 两个记忆来源都空 | 上表实测 |
| 2 | **不读本地资讯池** | 只有 `search_stock_news`（走 Bocha），没有读 `intelligence_items` 的工具 |
| 3 | 搜索 API 未配 | `news_intel` 只有 10 行 |
| 4 | 回测工具在但无数据 | `backtest_results` 0 行 |

### 要改什么

| 阶段 | 改动 |
|---|---|
| **1** | **闭环修好后，两个记忆来源自动有内容** —— 这是问股最大的提升，且不需要改问股代码 |
| 4 | 加一个读本地资讯池的工具（如 `get_local_intelligence(code)`），让问股能用上 RSS 源 |
| 2 | 搜索 API 配 key（或在没有 key 时明确告知，而不是静默返回空）|

## 功能 3 · 用资讯推测

### 怎么实现的

**不存在完整实现。** 有的是五个零件，其中四个是惰性的：

```
① decision_signals           记录判断           19 行  ✅ 在用
② decision_signal_outcomes   到期验证           19 行  ❌ 全 unable
③ GET outcomes/stats         命中率统计         端点在  ❌ 无数据
④ memory 反馈回路            置信度校准         已实现  ❌ 无数据
⑤ skill_opinion_outcomes     技能级验证         0 行    ❌
⑥ backtest_results           回测              0 行    ❌
```

**回路设计（完整的）**：

```
分析 → decision_signals → outcomes/run → hit_rate → memory.review
                                                          ↓
                                          confidence_adjustment → 影响下次分析
```

### 🔴 缺什么 —— **两端断**

```
输入端：18/19 是 watch → non_directional_action（且不可重试 → 永久死路）
数据端：stock_daily 停在 09-30（缺 10-08/10-09）
锚点端：19 个信号全部锚在 10-02/10-05（国庆假期）
代码端：000063 vs 000063.SZ 形态不一致；588200 完全无行情
```

### 要改什么

**全部在阶段 1**（这是整个项目最高价值的一步）：

| 改动 | 内容 |
|---|---|
| flat 分支 | `_direction_for_action` 加 `watch→flat`（2 行）+ `_classify_signal_outcome` 加 flat 分支（3 行）|
| 锚点走日历 | `resolve_historical_daily_bar_date`（已有 helper，别处已在用）|
| 可重试 | `non_directional_action` 加入 `RETRYABLE_UNABLE_REASONS` |
| 配置一致 | `neutral_band_pct` 硬编码 2.0 → 接 `backtest_neutral_band_pct` |
| 行情供给 | 独立刷新（补 10-08/10-09）+ 588200 |
| 身份统一 | `canonical_id` 读取路径 |
| 调度 | `run_outcomes` 接进 `runtime_scheduler`（现在只能手动调）|

**验收**：`unable` 从 19 降到 ≤1；能回答"过去 30 天方向命中率"。

## 功能 4 · 获取股票信息

### 怎么实现的

**HTTP 侧**：

```
GET /api/v1/stocks/{code}/profile         档案（含 intelligence 块，实测有数据）
GET /api/v1/history/{id}/markdown         报告原文
GET /api/v1/history/{id}/news             报告关联资讯
GET /api/v1/decision-signals/stocks/{code}/review   历史判断复盘
GET /api/v1/screening/history[/{run_id}]  选股历史
```

**Agent 侧**：见功能 2 的 19 个工具（行情/K线/筹码/技术/大盘）。

### 🔴 缺什么

| # | 问题 | 证据 |
|---|---|---|
| 1 | **数据陈旧，且"今天"是错的** | `get_analysis_context`（`storage.py:3489`，注释 `:3502-3505`）**显式忽略 `target_date`** → LLM 被告知 09-30 是"今天" |
| 2 | **抓到的数据被扔掉** | 今天 12:56:43 `analyze_trend` 抓到 600559 的 79 行，**不落库**（`side_effects` 里没有 `db_write`）|
| 3 | 代码形态不一致 | `stock_daily` 存 `000063.SZ`，`decision_signals` 存 `000063` → 查不到 |
| 4 | 覆盖有洞 | `588200` 在 `stock_daily` 完全没有行 |
| 5 | `force_refresh` 被丢弃 | API 声明了 → `process_single_stock` 没这个参数 |
| 6 | 组合估值失真 | `portfolio_repo.py:714-729` 按 `date <= as_of`，`as_of >= 10-01` 会取到 09-30 的价 |

### 要改什么

| 阶段 | 改动 |
|---|---|
| 1 | 补齐 `decision_signals` 里出现过的代码（含 588200）；身份统一 |
| 2 | `analyze_trend` 落库；`force_refresh` 接通 |
| 3 | **`get_analysis_context` 尊重 `target_date`** —— 最隐蔽的一条 |
| 3 | 断点续传语义修正（假期的"目标日期"不是"今天"）|
| 2 | 独立行情刷新任务（不依赖分析触发）|

## 一句话总结

| 功能 | 实现状态 | 核心缺口 |
|---|---|---|
| **选股** | 引擎完整（10 策略、快照、因子、LLM 排序）| **资讯覆盖为 0**，加集成是负收益 |
| **问股** | 19 个工具齐全，记忆机制完整 | **记忆源全空** —— 修闭环即自动改善 |
| **用资讯推测** | 五个零件都在，**回路两端断** | 判断无方向 + 行情断供 |
| **获取股票信息** | 端点工具齐全 | **"今天"是错的**（09-30）|

> **四个功能没有一个缺"能力" —— 全都缺"数据"。**
> 这就是为什么阶段 1（让判断可验证）远比加新功能重要。
