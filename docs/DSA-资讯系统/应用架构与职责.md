# 应用架构与职责

三个应用，各自只做一件事。**RSSHub 和 NewsNow 不是同类备份，是互补的** —— 这是理解整套系统最关键的一点。

## 二、职责对照表

| | **RSSHub** | **NewsNow** | **DSA** |
|---|---|---|---|
| **端口** | 1200 | 5173 | 8010 |
| **一句话职责** | 网页 → RSS | 网页 → JSON | 抓取、存储、分析、展示 |
| **它不做什么** | 不存储、不分析、不做个股逻辑 | 同左 | 不做网页解析（交给前两者）|
| **主要产出** | `symbol` 级个股资讯 | `market` 级大盘资讯 | 分析报告 / 选股结果 / 对话 |
| **源数量** | 15（12 个股 + 3 大盘）| 5（全大盘）| 23 个源的总配置 |
| **缓存** | 5 分钟 | 10~30 分钟 | 20 分钟冷却 |
| **有状态吗** | 无 | 无 | **有**（SQLite）|
| **能换掉吗** | 能（官方镜像即可）| 能 | **不能** —— 这是你自己的项目 |
| **为什么要它** | 个股维度的源最多 | 大盘热榜聚合得好 | — |

### 为什么两个都要

它们**覆盖不同的维度，几乎没有重叠**：

```
              symbol 级（个股）        market 级（大盘）
RSSHub              12                      3
NewsNow              0                      5
                  ─────────            ─────────
                    主力在这              主力在这
```

- **只有 RSSHub** → 大盘热榜弱（拿不到财联社热门、金十数据）
- **只有 NewsNow** → 个股资讯全没了（自选股一条都收不到）

**这不是冗余，是分工。**

## 三、数据流（一次个股分析）

```
用户点「分析 老白干酒 (600559)」
        │
        ▼
DSA: analyze_stock("600559")
        │
        ├─ ① 需要资讯 → _load_persisted_intelligence_context
        │       ├─ 查 scope_type='symbol' AND scope_value='600559'
        │       │     ↑ 这些条目当初是 RSSHub 的
        │       │       /eastmoney/search/老白干酒 和 /xueqiu/stock_info/SH600559 抓来的
        │       └─ 兜底：查 scope_type='market'
        │             ↑ 这些来自 NewsNow 的 5 个大盘源 + RSSHub 的 3 个
        │
        ├─ ② 拼进 LLM 上下文 → 调 LLM 分析
        │
        └─ ③ 结果写入 analysis_history
```

**关键：第 ① 步读的是数据库，不是实时抓取。** 资讯必须**先被抓进池子**才可能被分析用到 —— 这正是 P0 要解决的问题（当前只有跑分析时才会顺带抓）。

## 四、对外接口（谁调谁）

| 调用方 | 被调用 | 协议 | 用途 |
|---|---|---|---|
| DSA → RSSHub | `GET http://127.0.0.1:1200/<route>` | HTTP (RSS/Atom) | 抓个股/大盘资讯 |
| DSA → NewsNow | `GET http://localhost:5173/api/s?id=<源>` | HTTP (JSON) | 抓大盘热榜 |
| 你 → DSA | `http://127.0.0.1:8010` | HTTP | Web UI + API |
| DSA → LLM | DeepSeek / SiliconFlow | HTTPS | 分析 |
| DSA → 搜索 | Bocha | HTTPS | 问股的联网搜索 |

**RSSHub 和 NewsNow 之间没有调用关系** —— 它们是并列的两个转换器。

## 五、部署形态

```
你本机
 ├─ RSSHub     :1200   pnpm run dev   （rsshub-verify/，fork 自 DIYgod/RSSHub）
 ├─ NewsNow    :5173   pnpm run dev   （newsnow-verify/，fork 自 newsnext/newsnow）
 └─ DSA        :8010   python webui.py （daily_stock_analysis/，你自己的项目）

统一由 ~/renjiebank/renjie问股/start-local.sh 启动
```

**三个服务都跑在本机，通过回环地址通信。** 没有外部依赖，除了：
- LLM API（DeepSeek）
- 搜索 API（Bocha，问股用）
- **资讯源本身**（RSSHub/NewsNow 去抓的那些站点）

## 六、几个容易搞混的点

| 容易搞混 | 事实 |
|---|---|
| NewsNow 是 RSSHub 的备份？ | **不是。** 一个供个股、一个供大盘，覆盖不同维度。 |
| `localhost` 和 `127.0.0.1` 通用？ | **NewsNow 只绑 IPv6**，必须写 `localhost`。 |
| RSSHub 的源都在 `rsshub-verify` 里改？ | **不在。** 源配置在 DSA 的 `intelligence_sources` 表里，RSSHub 只负责把网页转成 RSS。加源是在 DSA 里加一条记录，指向某个 RSSHub 路由。 |
| 三个项目要一起改才能加资讯源？ | **不一定。** 如果目标站 RSSHub 已有路由，只改 DSA 就够了。只有目标站**没有现成路由**时才需要动 RSSHub（这正是 fork 它的原因）。 |
| `pipeline._analyze_with_agent` 是问股？ | **不是。** 它是被 `analyze_stock` 调用的「Agent 后端的个股分析」。问股走 `AgentExecutor`，完全不碰资讯池。 |
